# plan-issue

Issue の内容を把握し、実装計画をまとめ、ユーザーの承認後にプランファイルへ記録する。

## 手順

### 1. 情報収集

以下を並列で読み込む。
- `gh issue view <number>`（Issueの内容・ラベル・コメント）
- `docs/ARCHITECTURE.md`（設計方針・レイヤー構成）

Explore エージェントを起動し、Issue の解決に必要なコードベースの調査を行う。

### 2. 実装計画の提案

収集した情報をもとに実装計画を策定し、ユーザーに提案する。
提案には以下を含める。

- 変更するファイルと変更内容の概要
- 実装の順序（依存関係がある場合）
- `ARCHITECTURE.md` の設計方針との整合性
- 懸念点・リスク・代替案があれば明記

**ユーザーの明示的な承認を得てから次のステップへ進むこと。**
質問・修正・議論はここで行う。

### 3. 計画の記録

承認された計画を `.claude/tmp/plan-<number>.md` に記録する。

```markdown
# plan-<number>

## 実装方針
<承認された方針の概要>

## 変更ファイル一覧
- `<ファイルパス>`: <変更内容>

## 実装順序
1. <最初に変更するファイル・理由>
2. <次に変更するファイル・理由>

## 注意点
<懸念点・実装時に気をつけること>
```
