# plan-issue

Plan サブエージェントに調査と計画を委ね、ユーザーのレビューと議論を経て承認まで進める。

## 手順

### 1. Plan サブエージェントで調査・計画

Agent ツール（`subagent_type: Plan`）を起動し、以下を渡す。

```
Issue #<number> の実装計画を立ててください。

## 調査してほしいこと
- `gh issue view <number>` でIssueの内容・ラベル・コメントを確認
- `docs/ARCHITECTURE.md` で設計方針・レイヤー構成を確認
- 変更が必要なファイルと該当箇所
- 関連するクラス・関数・コンポーネント
- 影響範囲（呼び出し元・呼び出し先）

## レポートのフォーマット

以下の形式でレポートを返してください（ファイルへの書き出しは不要です）。

# plan-<number>

## 実装方針
<方針の概要>

## 変更ファイル一覧
- `<ファイルパス>`: <変更内容>

## 実装順序
1. <最初に変更するファイル・理由>
2. <次に変更するファイル・理由>

## 注意点
<懸念点・実装時に気をつけること>
```

### 2. プランファイルの書き出し

Plan エージェントのレポートをもとに、親が `tmp/plan-<number>.md` を作成する。

作成後、クリッカブルなリンクでユーザーに提示する。

```
計画を記録しました → [plan-<number>.md](tmp/plan-<number>.md)
```

計画の概要（変更ファイル・実装順序・懸念点）をその場でも要約して伝える。

### 3. レビューループ

**ユーザーの明示的な承認を得るまでこのループを続ける。**

ユーザーからのフィードバックの種類に応じて以下を使い分ける。

| フィードバックの種類 | 対応 |
|---|---|
| 計画の修正・方針変更 | Agent ツール（`subagent_type: Plan`）を再起動し、現在のプランファイルの内容と修正点を渡してレポートを返させる。受け取ったレポートをもとに親がプランファイルを上書きする |
| コードベースへの質問（「〇〇はどこで使われてる？」など） | Agent ツール（`subagent_type: Explore`）を起動して調査し、結果をユーザーに伝える |
| 軽微な文言修正 | 親が直接プランファイルを編集する |

Plan 再起動時のプロンプト例：

```
現在の計画を以下に示します。修正点を反映した計画をレポートとして返してください
（ファイルへの書き出しは不要です）。

## 現在の計画
<プランファイルの内容>

## 修正点
<修正点>
```

承認後、次フェーズ（implement-issue）へ進む。
