# plan-issue

Issue の内容を把握し、実装計画をファイルに記録したうえでユーザーのレビューを受ける。

## 手順

### 1. 情報収集

Agent ツール（`subagent_type: Explore`）を使用し、以下を調査する。

- `gh issue view <number>`（Issueの内容・ラベル・コメント）
- `docs/ARCHITECTURE.md`（設計方針・レイヤー構成）
- Issue の解決に必要なコードベース（変更箇所・関連クラス・影響範囲）

Explore エージェントへのプロンプト例：
```
Issue #<number>「<タイトル>」の実装に必要なコードを調査してください。
- 変更が必要なファイルと該当箇所
- 関連するクラス・関数・コンポーネント
- 影響範囲（呼び出し元・呼び出し先）
ファイル操作は Glob・Grep・Read を優先してください。
```

### 2. 計画の記録

収集した情報をもとに実装計画を策定し、`.claude/tmp/plan-<number>.md` に記録する。

```markdown
# plan-<number>

## 実装方針
<方針の概要>

## 変更ファイル一覧
- `<ファイルパス>`: <変更内容>

## 実装順序
1. <最初に変更するファイル・理由>
2. <次に変更するファイル・理由>

## 注意点
<懸念点・実装時に気をつけること>
```

ファイルを作成したら、クリッカブルなリンクでユーザーに提示する。

```
計画を記録しました → [plan-<number>.md](.claude/tmp/plan-<number>.md)
```

### 3. レビューと承認

**ユーザーの明示的な承認を得てから次のステップへ進むこと。**
提案には以下を含め、ファイルを確認してもらう。

- 変更するファイルと変更内容の概要
- 実装の順序（依存関係がある場合）
- `ARCHITECTURE.md` の設計方針との整合性
- 懸念点・リスク・代替案があれば明記

質問・修正・議論はここで行い、承認後にファイルを更新してから次フェーズへ進む。
