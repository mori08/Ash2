# コードベース理解度クイズ

ユーザーが自プロジェクトのコードを自分の頭で読む習慣をつけ、AIへの依存でコードリーディング力が衰えないようにするためのスキル。

1回の呼び出しで1問だけ出題する。続けて解きたい場合はユーザーが再びスキルを呼ぶ。

## Step 1: サブエージェントで問題ファイルを生成する

サブエージェントを1つ起動し、以下を指示する。

### サブエージェントへの指示内容

ファイル操作は Glob（探索）・Grep（検索）・Read（読み込み）・Write（保存）を優先する。

**目的：** コードベースを探索して問題を1問作成し、ファイルに保存してファイル名だけを返すこと。

**準備：**
- `tmp/quiz.log` を読む（存在しない場合はスキップ）
- 直近の出題履歴を確認し、同じ問題・同じファイルへの偏りを避ける

**探索方法：**
- `docs/ARCHITECTURE.md` でプロジェクト構成を把握する
- `docs/REFERENCE.md` でコンポーネント・システム・フェーズの一覧を把握する
- `Ash2/src/` 以下の `.hpp` / `.cpp` を Glob・Grep で探索し、出題対象を決定する

**避けるもの：**
- 自動生成ファイル
- 設定値の羅列のみで処理がないファイル
- 問題文にファイルパスを含めること（どこを読めばよいかが直接わかってしまうため）

**良い問題の条件：**
- コードを実際に読まないと答えられない（知識だけでは不可）
- 関数の役割・処理の流れ・エッジケース・副作用・型の意味など、幅広いレベルで出題してよい

**問題タイプのバリエーション：**

| タイプ | 例 |
|--------|-----|
| 役割 | 「`AttachmentSystem::UpdateTransform` は何をする関数か」 |
| 処理の流れ | 「`PhaseStack::update` でフェーズが `Pop` を返したとき、何が起きるか」 |
| エッジケース | 「`Hierarchy::Detach` を呼ばずにエンティティを削除するとどうなるか」 |
| 設計の意図 | 「`WorldPos` を子エンティティにも持たせているのはなぜか」 |
| 副作用 | 「`PhaseStack` に新しいフェーズを Push すると、既存のフェーズはどうなるか」 |
| 型・データ | 「`Drawable` が `variant` になっているのはなぜか」 |

**難易度の基準：**

| 難易度 | 記号 | 基準 |
|--------|------|------|
| easy | ⭐ | 該当箇所だけ読めば答えられる |
| medium | ⭐⭐ | 複数ファイルをまたぐ、または制御フローを追う必要がある |
| hard | ⭐⭐⭐ | 設計の意図や複数の概念の相互作用を理解していないと答えられない |

**問題ファイルのフォーマット：**

難易度（記号とラベル）と問いのみを記載する。ファイル名・関数名・ヒントは含めない。

**保存先：** `tmp/quiz_YYYYMMDD_HHMMSS.md`（現在日時を使う）

**返すもの：** ファイル名のみ（ファイルの中身は返さない）

## Step 2: ファイル名の案内

サブエージェントが返したファイル名をユーザーに伝え、ファイルを開いて問題を確認するよう案内する。
回答の準備ができたら送るよう伝える。

**問題ファイルの中身はユーザーが回答を送るまで読まない。**

## Step 3: 回答の受け取りと採点

ユーザーが回答を送ったら、問題ファイルを読んで採点する。

### 採点の方針

- 完全一致ではなく「本質的な理解ができているか」で判定する
- 部分的に正しい場合は正しかった点・足りなかった点を具体的に伝える
- 間違っていても責めず、理解を深める方向でフィードバックする
- AIも間違える可能性があるため、ユーザーとの議論で調整する姿勢を持つ

### フィードバックフォーマット

以下の要素を含めてフィードバックする。

- 判定（✅ 正解 / ⚠️ 惜しい / ❌ 不正解）
- 正しかった点・足りなかった点（具体的に）
- 補足（設計の意図・背景など、あれば）

### スキップを求められた場合

問題ファイルを読んで解説し、Step 4 へ進む。

## Step 4: ログの更新とファイルの削除

採点（またはスキップ）完了後、以下の順で処理する。

1. `tmp/quiz.log` に1行追記する（存在しない場合は新規作成）
2. 問題ファイルを削除する

ログのフォーマット：

```
2026-05-30 | easy   | correct   | AttachmentSystem::UpdateTransform の役割       | 子エンティティのワールド座標を親に追従して更新する
2026-05-30 | hard   | partial   | Hierarchy::Detach を呼ばずに削除した場合の挙動 | 子が残るとは答えられたが親参照の破損に言及なし
```

列の定義:
- `date`: 出題日（YYYY-MM-DD）
- `difficulty`: `easy` / `medium` / `hard`
- `result`: `correct` / `partial` / `incorrect`
- `question`: 問いの要約（1行）
- `user_answer`: ユーザーの回答の要約（1行）
