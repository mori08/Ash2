# implement-issue

プランファイルを読み込み、ブランチを作成した上で実装・検証ループを回す。
全チェック通過後にユーザーの承認を得て完了とする。

## 手順

### 1. 準備

`$ARGUMENTS` から Issue 番号を取得し、`tmp/plan-<number>.md` と `gh issue view <number>` の本文を読み込む。
Issue のラベルと実装方針から GIT.md の命名規則に従いブランチ名を決め、作成する。

```bash
git checkout -b <branch-name>
```

### 2. 実装ループ

a〜c を順番に実行する。NG が出た時点で d へ進み、a に戻る。

#### a. Implement サブエージェント

Agent ツール（`subagent_type: implement`）を起動し、プランファイルのパスを渡して実装させる。

#### b. CI サブエージェント

Implement エージェントの出力から変更ファイル一覧を取り出し、Issue 番号・Issue 本文とともにプロンプトに含めて Agent ツール（`subagent_type: ci`）を起動する。

#### c. ビジュアルチェック（ゲームを実行してテストしたい箇所がある場合）

`/run` スキルを使ってゲームを起動し、表示・挙動・操作感を確認する。

#### d. NG の処理

NG レポートの規模に応じて以下のいずれかを選択する。
プランで検討・却下済みの選択肢を再提案する指摘は、その旨と却下理由を添えてユーザーに提示する。

**1. 軽微な修正**（typo・フォーマット・警告1件など）
ユーザーへの確認なしに修正方針を決め、プランファイルの末尾に追記して a に戻る。

**2. 中程度な修正**（ロジック変更・設計の調整など）
修正プランをユーザーに提示してレビューを依頼し、議論・承認を得てからプランファイルに追記して a に戻る。

**3. 大規模な修正**（方針の根本的な見直しが必要な場合）
このセッションを中断し、`/resolve-issue` の再実行（Phase 1 からやり直し）を提案する。

プランへの追記フォーマット（1・2の場合）：

```markdown
## § 修正 <N回目>
<NG の内容と修正方針>
```

### 3. 完了報告と承認

全チェック通過後、変更の概要と CI レポートをユーザーに報告し、承認を得る。

CI レポートは、ループ中に NG を出した段階を段階ごとにまとめる。
各回の NG レポートとプランファイルの `## § 修正 <N回目>` からまとめ、ルール準拠は節名を添える。

```markdown
- <段階番号>. <段階名>
  - (<N>回目) <検出した内容>
```
