# ファイルの提示方法

会話の応答でファイルに言及するときは、目的に応じて以下の3レベルを使い分ける。

- レベル1: 文中で軽く触れるだけのファイル
- レベル2: ユーザーが確認する可能性があるファイル
- レベル3: ユーザーに確実に確認してほしいファイル

このルールは会話の応答にのみ適用する。
コード・コードコメント・GitHub Issue/PR 本文には適用しない。

## パスの書式（共通）

どのレベルでも、パスは以下の書式で書く。

- リポジトリのルートからの相対パスを `docs/hoge.md` の形で書く
- パスの直前・直後には空白を入れる（理由: 空白を入れずに文字を続けると、前後の文字列までパスの一部として判定されるため）
- 特定の行を指す場合は `docs/hoge.md:20` の形式を使う

## レベル1: 文中で触れる

対応の中で軽く触れる程度のファイルは、文中にパスを入れるだけでよい。

## レベル2: 最後にまとめる

ユーザーが確認する可能性があるファイルは、応答の最後にまとめて提示する。
変更・作成したファイルや、結論の根拠として参照したファイルが対象。

フォーマット:

```
- 説明
  - `path`
- 説明
  - `path:20`
```

## レベル3: code で開く

ユーザーに確実に確認してほしいファイルは、IDE で開いて提示する。
その応答の主目的がそのファイルのレビュー・確認であるときのみ使う。

- Bash で `code <パス>` を実行して IDE で開く
- 1度の応答で code で開くファイルは1つ以下にする
- レベル3で開いたファイルもレベル2のまとめに載せる（理由: まとめだけで対象ファイルを一覧できるようにするため）
