# PLAN_FORMAT.md

plan ファイル（`tmp/plan-<番号>.md`）の書き方を定める。

## 対象

- 対象は resolve-issue フローが作成・追記する plan ファイルのみ
  - `tmp/plan-<番号>.md`
- 他の文書（会話の応答・issue / PR・コードコメント等）には適用しない

## 節で分ける

- `###` の見出しを使って、段落に該当する節を作る
  - `##` は固定セクション（`## § 実装方針` 等）専用とし、節には使わない
    - 固定セクションの構成は plan-issue / implement-issue スキルが定める
- 見出しは短く端的に、節の内容を要約したものにする
- 節が巨大化しすぎないように気をつける
  - 推奨は4~10行くらい
  - 20行超える場合は分割した方がよいが、節としてのまとまりと行の短さの方が優先

## 箇条書きで一行を短く区切る

- 節内は箇条書きで記載する
  - リストマーカーは `-` を使う
  - 手順を表現するときは、`1.` `2.` のリストマーカーを使う
  - 地の文やリード文は置かない（区切りを作りたい場合は `###` の見出しにする）
- 一行一文で書き、一文が長くなりすぎないように気をつける
  - 一文で全て表現しようとしない
  - 補足や理由は文に混ぜず、インデントを上げ次行へ逃がす
  - 一行が全角60文字(半角120文字)程度を超えるような文章は長文とみなす
- 一文の途中で改行は避ける
  - 改行がどうしても必要な場合は、文節・インラインコードの途中では切らない
- 同種の項目は同じ雛形・同じ語順で書く
- インラインコードは文を長くしやすいので使い方に気をつける
  - 次行へ逃がすことで文章の長文化を避ける
  - 例）以下のコンポーネントを参照する
    - `WorldPos`
    - `Velocity`
      - `h` を参照し、地面クランプ時は 0 にする
- 箇条書き内では端的に書く
  - このファイルのような文体を使う
  - 敬語などは使わず、句点は必要ない

## ファイルパスはリンクにする

- ファイルパスは、元ファイルへ飛べる参照スタイルリンクで書く（最優先の価値）
  - 本文には `[ファイル名 L行番号]` だけを書き、文中に長いパスを混ぜない
    - 例: [GravitySystem.cpp L8-21]
  - パス定義は `§` セクションの末尾にまとめる
    - 形式: `[ファイル名 L行番号]: plan ファイルからの相対パス#L行番号`
- 行番号はオプション（不要 / `#L行番号` / `#L開始行-L終了行`）
- パス定義の行は行の長さの制限に含めない

[GravitySystem.cpp L8-21]: ../Ash2/src/System/GravitySystem.cpp#L8-L21

## コードブロックを使う

- 文章で説明するより、実例を示した方が分かりやすい場合はコードブロックを使う
- コードブロックの行数、文字数は他の制限を無視して良い
  - 「節は20行以内、一行が全角60文字以内」の制限にコードブロックを含めない
- 一つのコードブロックが巨大化しすぎないように注意
  - 巨大な関数を全て抜き出すことはせず、該当箇所を抽出して記載する
  - 論点内で重要ではない箇所は省略してよい
    - `// 略（要約）` のように省略したと分かるようにはする
- 参照元があるときは、コードブロック直前の行に `[ファイル名 L行番号]` を書く

[GravitySystem.cpp L8-21]

```cpp
void GravitySystem::Update(entt::registry& registry, double dt) {
  auto view =
      registry.view<WorldPos, Velocity, Gravity>(entt::exclude<Hitstop>);
  for (auto&& [entity, pos, vel, gravity] : view.each()) {
    // 次フレーム用の重力加速
    vel.h -= gravity.accel * dt;
    // 略（地面クランプ）
  }
}
```

- 変更を強調したいときはdiffを使う

```diff

+  auto view =
+      registry.view<WorldPos, Velocity, Gravity>(entt::exclude<Hitstop>);
```
