# DOCUMENTATION.md

プロジェクト構造ドキュメント（ARCHITECTURE.md / REFERENCE.md）の記述ルール。

## 2つのドキュメントの分担

**ARCHITECTURE.md は全体の構成を説明する。** 何がどう組み合わさって動いているかを、初めて
このコードに触れる人が通しで読んで掴めるように書く。読み終えたとき、REFERENCE.md に並ぶ部品が
それぞれどこに差さるものか分かっている、という状態を目指す。

**REFERENCE.md は個々の部品を一覧する。** 目的の部品がどこにあり何をするかを、必要なときに
必要な行だけ引く。通読は想定しない。

| | 書くこと | 増え方 |
|---|---|---|
| [ARCHITECTURE.md](../ARCHITECTURE.md) | 全体の構成 | 機能を足しても増えない |
| [REFERENCE.md](../REFERENCE.md) | 部品そのものの一覧（コンポーネント・システム・フェーズ・入力・アセット） | 部品が増えるたびに線形に増える |

読み方が違うため、分量の扱いも違う。ARCHITECTURE.md は通読できる長さに保ち（300行上限）、
REFERENCE.md には上限を設けない。

ARCHITECTURE.md が目指すのは、短い時間で広い範囲を掴めること。網羅性はそれに劣後する。
全体の構造に関わる情報であっても、些細なものは省く。行数に余裕があっても省く。

全体の構成として書くのは、変わったら設計そのものが揺らぐものに限る。実装を進める過程で普通に
変わるものは、広く使われていても全体の構成には含めない。当たり判定の形状や判定方法はこれにあたる。

同じ事実を両方に書かない。一方には参照だけを残す。

## ARCHITECTURE.md

### 書き方

**構造を説明する。用語の一覧にしない。** その仕組みが何を可能にしているかを先に書き、
型の名前はその中で自然に出す。「誰が何を知らないか」「どこに閉じているか」のように、
責任の所在が見出しだけで分かる形にする。

**呼び出しの連鎖は図で示す。** コード例より短く、本筋だけが残る。

```
Main.cpp ── registry を1つ作る
  └ PhaseStack::update(registry, frameData)
       └ IPhase::update(registry, frameData)    ← 先頭のフェーズだけ
            └ 各 System::Update(registry, ...)  ← そのフェーズに必要なものを順に
```

**呼び名はコードの識別子に合わせる。** ECS のように外部の標準語彙があるものはそれを使うが、
このプロジェクト固有の仕組みに新しい訳語を作らない。

**書かないもの。** 採らなかった選択肢とその理由、部品名の列挙、コードを書くときの注意、
文書自身についての説明（読み方・章立ての意図）。

### 300行上限

ここでの説明は機能を足しても増えないため、行数が伸び続けるなら個々の機能の話が混ざっている。
超過しそうな場合は以下の優先順位で削る。

1. コード例
2. 特定の部品1つにしか効かない説明
3. 実装の詳細（メンバ構成・分岐条件・評価順）
4. 現在使われていない設計の説明

削ってはいけないもの：全体の構成と、複数の仕組みにまたがる制約

## REFERENCE.md

### 書き方

「何があるか」と「どこを見ればよいか」を引くためのドキュメント。一覧性を保つため、
原則としてテーブル形式で書く。

行数上限はないが、1エントリの説明を無制限に長くしてよいわけではない。1つのテーブルセルに
複数の関心事を詰め込みそうな場合は、詰め込まずに別のドキュメントへ出し、参照だけを残す。
ゲームデザイン上の仕様（区間の秒数・キャンセル可否・リアクション Lv など）は
`docs/game_design/` 配下へ出す。

テーブルの列に収まらない例外だけ、節末の箇条書きに残してよい。

### ファイルへのリンク

クラス・システム・フェーズなどを一覧するテーブルでは、名前をリポジトリルートからの
相対パスリンクにする。リンク形式は `[ClassName](../Ash2/src/Path/To/File.hpp)`
（`docs/` からの相対パス）。

リンク化するのは部品一覧テーブルの名前だけ。本文中でアセット・設定ファイルを指すときは、
リポジトリルートからの相対パスをバッククォートで書く
（例: `` `Ash2/App/assets/config/player.toml` ``）。ワイルドカードを含むパスは
リンクにできないため、この種のパスはリンク化せず表記を揃える。
