# ECS.md

EnTT を使うコードの書き方。ECS の位置づけと全体像は
[ARCHITECTURE.md](../ARCHITECTURE.md) の「2. ECS」を参照。

## 1. コンポーネントを足すとき

### 派生データは手で登録しない

名前引きなどの派生データは `on_construct` / `on_destroy` のシグナルで同期する。
呼び出し側が登録・削除を書く必要はない。

シグナルは構築・破棄でしか飛ばないため、同期のキーになるフィールドは構築後に変更できない。
そのようなフィールドは `const` にする。

## 2. システムを書くとき

### フレームをまたぐ状態を持たない

システムは静的関数で、メンバ変数もファイルスコープの可変変数も持たない。
持ち越したい状態はコンポーネントか `registry.ctx()` に置く。

### 時間で進むシステムは Hitstop への態度を決める

次のどちらかを選ぶ。

| 選択 | 挙動 |
|---|---|
| `entt::exclude<Hitstop>` でビューから外す | 完全に止まる |
| 除外せず `dt = 0` の `FrameData` で呼ぶ | 時間だけが凍結し、入力の受付は続く |

既存の対応は [REFERENCE.md](../REFERENCE.md) の `Hitstop` の項を参照。

## 3. ビューを書くとき

### 種別ごとの分岐を作らない

エンティティの種別で `if` を書かない。必要なコンポーネントが揃っているエンティティだけが
ビューに入る形で能力を表す。

種別タグ（`Player` / `Enemy` / `Projectile`）は、ビューの絞り込みに使う。
ビューに入れたうえで `if` で振り分けるのは、コンポーネントの選び方が合っていない兆候。

### 振る舞いを止めるときはビューから外す

フラグを見て分岐せず、タグを付けて `entt::exclude` で外す。除外の意図がクエリに現れる。

```cpp
// 避ける：走査してから捨てる
for (auto&& [e, pos, vel] : registry.view<WorldPos, Velocity>().each()) {
  if (registry.all_of<Hitstop>(e)) continue;
}

// こう書く：最初から入らない
registry.view<WorldPos, Velocity>(entt::exclude<Hitstop>)
```

`Invincible` を持つエンティティを被弾対象から外す、といった一時的な無効化も同じ形で書く。
コンポーネント側に `bool` のスイッチを持たせない。

## 4. エンティティを破棄するとき

### 破棄は親から

`Hierarchy` を持つエンティティは `Hierarchy::DestroyWithChildren` で破棄する。
子は連動して破棄されるため、個別に消す必要はない。

親から切り離した独立エンティティ（弾、フェード中のもの）は連動しない。
タグで検索して個別に破棄する。

### ビューの走査中に destroy しない

破棄対象は配列に集め、ループを抜けてからまとめて破棄する。
