# COMMENT.md

`.cpp` / `.hpp` 共通のコメント規約。

## Doxygen コメント

関数・構造体・メンバ変数には `///` で Doxygen コメントを書く。言語は日本語。
**名前・型・シグネチャから読み取れない情報**のみ記述する。設計の経緯・実装の動機は書かない。

- 関数: `@brief` / `@param` / `@return`（いずれも非自明な場合のみ）
- 構造体: `@brief` で一行説明
- メンバ変数: `///` で一行説明（前置）
- `@note`: 前提条件・呼び出し順序など、コードからは気づけない制約

記入例（例示用の架空コード。実コードとは同期しない）：

```cpp
/// @brief 円形の当たり判定
struct HitCircle {
  /// 中心のワールド座標
  Vec2 center{0.0, 0.0};
  /// 半径（ピクセル）
  double radius = 0.0;

  /// @brief 点が判定内にあるか
  /// @return 境界線上を含めて true
  [[nodiscard]] bool contains(Vec2 point) const;
};

/// @brief 半径の大きい順の比較（std::sort 用）
/// @return a が b より半径が大きい場合 true
inline bool RadiusGreater(const HitCircle& a, const HitCircle& b);
```

## 注記コメント

`//` で書く。

### Why not コメント

自然に書いたら別の実装になる箇所で、その理由がコードから読み取れない場合のみ記述する。

### TODO コメント

未解決の問題を `// TODO(#<Issue番号>): <症状>` の形式で書く。

- 書く: 何が問題か（症状・制約・未対応の範囲）
- 書かない: どう直すか（解決方法・実装案・着手の見通し）
- Issue 番号を伴わない TODO は書かない
- その Issue を解決する PR の中で削除する

### 定数の背景

マジックナンバーを定数にしたとき、値の選び方に背景があれば書く。
「何の値か」は名前で表し、コメントには「なぜその値か」だけを書く。

- 書く: 制約から決まる値（誤差対策・仕様上の限界・他の値との関係・アルゴリズム上の要請）
- 書かない: 見た目や手触りの調整値。背景がない値に理由を作文しない
